# File storage providers

Application services depend on `IFileStorageService`; provider SDKs live in the provider adapters. Existing deployments default to Aliyun OSS; the supplied VPS systemd unit selects Local storage for new uploads. Select Azure Blob using deployment environment variables (do not commit credentials):

- `FileStorage__Provider=AzureBlob`
- `AzureBlob__ConnectionString=<secret from deployment configuration>`
- `AzureBlob__PublicContainerName=<public container>`
- `AzureBlob__PrivateContainerName=<private container>`
- `AzureBlob__PublicBaseUrl=<optional CDN/container base URL>`

The public container must allow public reads for uploaded images and files whose URLs are stored in existing database fields. Keep the private container private; signed downloads use a read-only SAS URL. The connection string must use shared-key credentials for SAS generation.

To retain the current provider, use `FileStorage__Provider=AliyunOss` (or omit it) and keep the existing `ThaiDataCloud` configuration.

For temporary VPS-local storage, set these environment variables in `/etc/tiwhub/api.env` (never commit the signing key):

- `FileStorage__Provider=Local`
- `LocalFileStorage__RootPath=/var/lib/tiwhub-storage`
- `LocalFileStorage__SigningKey=<at least 32 random bytes; generate with openssl rand -base64 48>`

Run `deploy/setup-vps.sh` to create the persistent directories. Public objects are served read-only under `/uploads/`; private objects stay outside Nginx's public alias and course-material downloads use expiring HMAC-signed API URLs. Upload routes remain authenticated and keep their per-endpoint size/type/tenant checks. Do not add a public anonymous file-write endpoint. Back up `/var/lib/tiwhub-storage` along with the database.

To test before DNS is configured, use the SSH tunnel and Postman steps below. Do not send bearer tokens over the VPS's current public HTTP endpoint.

## Provider cutover checklist

1. Create both Azure containers and configure public-read access only on the public container.
2. Copy private course-material objects from OSS to the Azure private container with their exact existing object keys. Course-material rows store keys, not provider names.
3. Deploy Azure configuration and test public upload/URL reads, private upload, signed download, and deletion before turning down OSS.
4. Existing public-file URLs are persisted as absolute URLs in several records. They continue to point to OSS after the switch. Keep OSS available until those objects are copied and the stored URLs are migrated or otherwise served from their old locations.

Changing `FileStorage__Provider` switches new operations; it does not copy objects or rewrite existing database URLs by itself.

## Testing uploads on a VPS before DNS/HTTPS is ready

Do not add an anonymous `/upload` endpoint that writes arbitrary filenames into a public VPS folder. The API already has authenticated upload routes, validates each route's file type and size, and stores files through the configured OSS/Azure provider rather than a local `uploads` directory.

For a safe Postman test before DNS is ready, create an SSH local tunnel to the API's loopback-only Kestrel port:

```text
ssh -N -L 5000:127.0.0.1:5000 <ssh-user>@<vps-ip>
```

Keep the tunnel running, then configure Postman:

1. `POST http://127.0.0.1:5000/api/uploads/website-media`
2. Authorization → Bearer Token: use a short-lived test account token with an institute association.
3. Body → `form-data`; add key `file`, change its type to **File**, and select an image no larger than 5 MB.
4. A successful response returns JSON containing the uploaded file URL. With the supplied VPS service configuration, the object is stored in `/var/lib/tiwhub-storage/public`, not in `/var/www/my-api/uploads`.

The SSH tunnel encrypts traffic between the client and VPS. Do not send a real bearer token or private file to the VPS's public `http://<vps-ip>/api/...` endpoint; the current Nginx deployment has HTTP only. Use HTTPS before testing through the public IP/host. Nginx allows 25 MB request bodies on `/api/` to accommodate the API's 20 MB course-material limit; each endpoint still enforces its own lower file limit.

## Moving from Local to OSS/Azure later

Changing `FileStorage__Provider` affects new operations only. Copy private course-material objects using their existing `ObjectKey`s. Inventory URL-only public objects separately: URLs generated by Local use the stable `/uploads/...` path, while older records may contain absolute provider URLs and will need a redirect, URL rewrite, or retained old provider. Keep `/var/lib/tiwhub-storage` until the migration is verified.
