### 1. [สรุปคอนเซปต์แบบบ้านๆ]

ระบบนี้เปรียบเสมือน **"ระบบแจกกุญแจเข้าตึกที่รู้ใจและจำกัดสิทธิ์"** ครับ

ผู้ใช้งานแต่ละกลุ่ม (เจ้าของ, ครู, ผู้ปกครอง, นักเรียน) จะได้รับ "กุญแจ" เข้าตึกคนละแบบ:

* **เจ้าของ/Admin:** ได้กุญแจมาสเตอร์คีย์ เดินเข้าได้ทุกห้อง ดูข้อมูลและจัดการได้ทั้งหมด
* **ครูผู้สอน:** ได้กุญแจเข้าเฉพาะห้องเรียน เพื่อไปเช็คชื่อ ให้คะแนน และสั่งการบ้าน
* **ผู้ปกครอง:** มีความพิเศษคือไม่ต้องพกกุญแจปกติ แต่ใช้ "การจดจำใบหน้า" (เปรียบเทียบกับการใช้ LINE Login) เดินเข้าตึกเพื่อไปดูข้อมูลของลูกตัวเองได้เลยโดยอัตโนมัติ

---

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **การยืนยันตัวตน (Login):**
* หากเป็น Admin, ครู, หรือนักเรียน จะกรอกอีเมล/เบอร์โทร และ รหัสผ่าน เพื่อเข้าสู่ระบบ (FR-AUTH-01)
* หากเป็นผู้ปกครอง ระบบจะให้เข้าสู่ระบบผ่าน LINE Login โดยอัตโนมัติ (FR-AUTH-02)


2. **การตรวจสอบสิทธิ์ (Role Check):** เมื่อเข้ามาแล้ว ระบบจะเช็คว่าผู้ใช้ถือสิทธิ์อะไร (Role-based Access) และเปิดให้เห็นเฉพาะฟังก์ชันที่ตรงกับสิทธิ์นั้น (FR-AUTH-04)
3. **การลืมกุญแจ (Forgot Password):** หากผู้ใช้ลืมรหัสผ่าน สามารถกดขอรีเซ็ตรหัสผ่าน โดยระบบจะส่งลิงก์หรือรหัสไปทางอีเมลหรือ SMS (FR-AUTH-03)
4. **การบันทึกประวัติ (Audit):** ทุกครั้งที่มีการเข้าใช้งานหรือแก้ไขข้อมูลสำคัญ ระบบหลังบ้านจะจดบันทึกไว้เสมอว่าใครเป็นคนทำและทำเมื่อไหร่ (FR-AUTH-05, NFR-S-04)
5. **การตัดการเชื่อมต่อ (Timeout):** หาก Admin ล็อกอินทิ้งไว้แล้วไม่ได้ใช้งานเกิน 30 นาที ระบบจะเตะออกจากระบบอัตโนมัติเพื่อความปลอดภัย (NFR-S-06)

### 3. [ตารางสรุปข้อมูลที่ต้องเก็บ]

อ้างอิงจากโครงสร้างฐานข้อมูล (หมวด 6.1) ตาราง **`users` (ผู้ใช้งานทั้งหมด)**:

| หมวดหมู่ข้อมูล | ข้อมูลที่ต้องเก็บ (Field) | อธิบายแบบบ้านๆ (นำไปใช้ทำอะไร) |
| --- | --- | --- |
| **ข้อมูลประจำตัว** | `id` | รหัสประจำตัวของผู้ใช้ในระบบ |
|  | `email`, `phone` | อีเมลและเบอร์โทรศัพท์ สำหรับใช้พิมพ์ตอนล็อกอิน หรือส่งรหัสรีเซ็ตพาสเวิร์ด |
| **การเชื่อมต่อ LINE** | `line_user_id` | รหัสที่ได้จาก LINE เอาไว้จำว่า LINE ของผู้ปกครองคนนี้คือบัญชีไหน (เพื่อทำ Auto-Login) |
| **ความปลอดภัย** | `password_hash` | รหัสผ่านที่ถูกแปลงเป็นรหัสลับแล้ว (ห้ามเก็บรหัสผ่านจริง) |
| **สิทธิ์การใช้งาน** | `role` | ตำแหน่งในระบบ (เช่น admin, teacher, parent, student) เพื่อกำหนดว่าให้เห็นหน้าจอไหนบ้าง |

### 1. [สรุปคอนเซปต์แบบบ้านๆ]

ระบบนี้เปรียบเสมือน **"แฟ้มประวัติและเครื่องทำบัตรประจำตัวนักเรียน"** ประจำสถาบันครับ

เมื่อมีเด็กใหม่เข้ามาสมัคร พนักงานจะเปิดแฟ้มนี้เพื่อจดประวัติส่วนตัว ข้อควรระวังเรื่องสุขภาพ (เช่น แพ้อาหาร) และจดว่าใครคือคุณพ่อคุณแม่ พอจดเสร็จปุ๊บ ระบบจะ "พิมพ์บัตรประจำตัวที่มีรหัส QR Code" ออกมาให้อัตโนมัติ เพื่อให้นักเรียนเอาไว้ใช้สแกนเข้าประตูในครั้งต่อๆ ไป

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **การสร้างประวัติ (Register):** พนักงานเคาน์เตอร์ลงทะเบียนนักเรียนใหม่ โดยใส่ข้อมูลพื้นฐาน และอัปโหลดรูปถ่าย (FR-STD-01)
2. **การเฝ้าระวังสุขภาพ (Medical Alert):** พนักงานบันทึกโรคประจำตัว หรือประวัติการแพ้ยา/แพ้อาหารลงไป เพื่อให้คุณครูผู้สอนเห็นข้อมูลนี้ได้ทันทีและดูแลเด็กได้อย่างปลอดภัย (FR-STD-04)
3. **การผูกผู้ปกครอง (Parent Binding):** พนักงานบันทึกข้อมูลผู้ปกครอง (สามารถใส่ได้ 2 ท่านขึ้นไป) พร้อมเบอร์ติดต่อฉุกเฉิน (FR-STD-03) รวมถึงรายชื่อบุคคลที่ได้รับอนุญาตให้มารับเด็กกลับบ้าน (FR-STD-05)
4. **การออกบัตร (QR Generation):** เมื่อบันทึกเสร็จ ระบบจะสร้าง "บัตรนักเรียนดิจิทัลพร้อม QR Code" ให้โดยอัตโนมัติ (FR-STD-02) ซึ่งสามารถสั่งพิมพ์ออกมาเป็นไฟล์ PDF สำหรับนำไปทำบัตรแข็งได้ (FR-STD-08)
5. **การค้นหาและรายงาน (Search & Export):** เมื่อต้องการหาข้อมูลเด็ก พนักงานสามารถค้นหาด้วย ชื่อ, รหัส, หรือเบอร์โทรผู้ปกครองได้ทันที (FR-STD-06) และสามารถกด Export ข้อมูลรายชื่อออกมาเป็นไฟล์ Excel / CSV ได้ (FR-STD-07)

| หมวดหมู่ข้อมูล | ข้อมูลที่ต้องเก็บ (Field) | อธิบายแบบบ้านๆ (นำไปใช้ทำอะไร) |
| --- | --- | --- |
| **ข้อมูลนักเรียน (`students`)** | `id`, `full_name`, `nickname` | รหัส, ชื่อจริง, และชื่อเล่นของนักเรียน |
|  | `grade`, `school` | ระดับชั้นเรียน และโรงเรียนปกติที่เด็กกำลังศึกษาอยู่ |
|  | `photo_url` | ลิงก์รูปถ่ายของเด็ก สำหรับแสดงบนหน้าจอให้ครู/พนักงานเห็น |

|  | `qr_token` | รหัสลับของเด็ก ที่แปลงร่างเป็นภาพ QR Code สำหรับสแกนหน้าประตู |
| **ข้อมูลผู้ปกครอง (`parents`)** | `student_id` | เอาไว้จำว่าผู้ปกครองคนนี้ เป็นพ่อ/แม่ของนักเรียนคนไหน (เชื่อมข้อมูลกัน) |
|  | `full_name`, `phone`, `relationship` | ชื่อ, เบอร์โทรศัพท์, และความสัมพันธ์ (เช่น พ่อ, แม่, ป้า) |

### 1. [สรุปคอนเซปต์แบบบ้านๆ]

ระบบนี้เปรียบเสมือน **"เครื่องตอกบัตรเข้างาน + เครื่องตัดคูปองอัตโนมัติ"** ครับ

แทนที่ครูจะต้องมานั่งขานชื่อทีละคน เด็กนักเรียนแค่เอาบัตร QR Code ไปส่องที่กล้องมือถือของคุณครู ระบบจะทำหน้าที่จดเวลาเข้าเรียน ตัดคูปอง (โควต้าเรียน) ทันที และส่งข้อความรายงานผู้ปกครองอัตโนมัติ แถมถ้าเด็กคนไหนมาสายเกินเวลาที่กำหนด ระบบก็จะคอยฟ้องเตือนให้ด้วย และตอนกลับบ้านก็ยังสแกนเพื่อจดบันทึกได้อีกว่าใครเป็นคนมารับลูกกลับครับ

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **การสแกนเข้าเรียน (Check-in):** คุณครูเปิดกล้องมือถือสแกน QR Code ของนักเรียน (ใช้เวลาเปิด->สแกน->ยืนยัน ไม่เกิน 3 ขั้นตอน) หรือหากเด็กลืมบัตร ครูสามารถกดเช็คสถานะด้วยมือเองได้ (มาเรียน/สาย/ลา/ขาด) (FR-ATT-01, FR-ATT-05, NFR-U-01)
2. **การประมวลผลหลังบ้าน (Processing):**
* ระบบตรวจสอบก่อนว่านักเรียนคนนี้สแกนคลาสนี้ไปหรือยัง เพื่อป้องกันการสแกนซ้ำ (FR-ATT-07)
* หากผ่าน ระบบจะบันทึกเวลาเข้าเรียน (Timestamp) และ **"หักจำนวนครั้งคงเหลือ"** ของคอร์สเรียนนั้นลง 1 ครั้งโดยอัตโนมัติ (FR-ATT-02, FR-ATT-08)


3. **การแจ้งเตือนทันที (Real-time Alert):** ระบบส่งข้อความ Push Notification ผ่าน LINE แจ้งผู้ปกครองทันทีว่านักเรียนเข้าเรียนแล้ว (FR-ATT-03)
4. **ระบบเฝ้าระวังคนมาสาย (Late Alert):** หากถึงเวลาเริ่มเรียนไปแล้ว 20 นาที แต่ยังมีเด็กในคลาสที่ยังไม่ได้สแกนชื่อ ระบบจะแจ้งเตือนอัตโนมัติ (FR-ATT-04)
5. **การสแกนกลับบ้าน (Check-out):** เมื่อเลิกเรียน นักเรียนสแกน QR Code อีกครั้งเพื่อบันทึกเวลาออก และพนักงาน/ครู บันทึกข้อมูลว่าใครเป็นคนมารับ (เช่น พ่อ, แม่, รถรับส่ง) พร้อมส่ง LINE แจ้งผู้ปกครองอีกรอบ (FR-ATT-02, FR-ATT-06)

### 1. [สรุปคอนเซปต์แบบบ้านๆ]

ระบบนี้เปรียบเสมือน **"ระบบคืนตั๋วและจองที่นั่งสำรองอัตโนมัติ"** ครับ

เมื่อก่อนถ้าเด็กป่วย ผู้ปกครองต้องโทรมาลา ครูต้องจดลงสมุด แล้วค่อยหาเวลาให้เด็กมานั่งแทรกเรียนชดเชยวันหลัง วุ่นวายไปหมด แต่ด้วยระบบนี้ ผู้ปกครองแค่กด "ขอลา" ผ่านแอป LINE ถ้าระบบดูแล้วว่าลาถูกต้องตามกฎ ก็จะเสก **"คูปองเรียนชดเชย"** คืนให้ในระบบทันที จากนั้นคุณแม่ก็นำคูปองนี้ไปกดจิ้มเลือก "ที่นั่งว่าง" ในคลาสอื่นเพื่อจองเรียนชดเชยให้ลูกได้เองเลย โดยไม่ต้องโทรคุยกับสถาบันให้เสียเวลาครับ

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **การแจ้งลา (Leave Request):** ผู้ปกครองกดแจ้งลาผ่าน LINE LIFF App โดยระบุวันที่ เหตุผล และแนบรูป (เช่น ใบรับรองแพทย์) หรือคุณครูจะกรอกข้อมูลแทนผู้ปกครองก็ได้ (FR-LV-01, FR-LV-02)
2. **คัดกรองและอนุมัติอัตโนมัติ:** ระบบจะดูเวลาที่แจ้งลา แล้วแยกประเภทว่าเป็นการ "ลาล่วงหน้า", "ลากะทันหัน", หรือ "ขาดเรียน" จากนั้นระบบจะใช้กฎที่ตั้งไว้มาตัดสินใจให้อัตโนมัติว่า เด็กคนนี้สมควรได้รับสิทธิ์เรียนชดเชยหรือไม่ (FR-LV-03, FR-LV-04)
3. **การแจกคูปอง (Make-up Credit):** หากระบบอนุมัติให้ลา ระบบจะสร้าง "เครดิตเรียนชดเชย (คูปอง)" ผูกกับชื่อนักเรียนคนนั้น พร้อมกำหนดวันหมดอายุของคูปอง (FR-LV-05)
4. **เปิดที่นั่งสำรอง (Slot Creation):** คุณครูเข้าไปเปิดห้องเรียนสำหรับชดเชย (Slot) โดยกำหนดวัน เวลา และระบุ "จำนวนที่นั่งรับได้" (FR-LV-06)
5. **การจองชดเชย (Booking):** ผู้ปกครองเปิด LINE LIFF จะเห็นตาราง Slot ที่ว่างอยู่ แล้วกดจองที่นั่งชดเชยให้ลูกได้เลย (FR-LV-07)
6. **กรณีฉุกเฉิน (Edge Cases):**
* หากครูยกเลิกคลาส (Group Cancel) ระบบจะคืนคูปองกลับให้เด็กทุกคนอัตโนมัติ (FR-LV-08)
* หากผู้ปกครองกดจองเรียนชดเชยไว้แล้ว แต่ถึงเวลาจริงเด็ก "เบี้ยวไม่มา (No-show)" ระบบจะยึดคูปองนั้นทิ้งอัตโนมัติ (FR-LV-09)

### 1. [สรุปคอนเซปต์แบบบ้านๆ]

ระบบนี้เปรียบเสมือน **"การ์ดพลังตัวละครในเกม (RPG) หรือ สมุดพกยุคดิจิทัล"** ครับ

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **ตั้งเป้าหมาย (Set Topics):** ก่อนเริ่มคอร์ส คุณครูจะสร้าง "หัวข้อบทเรียน" ไว้ล่วงหน้า (เช่น บทที่ 1, บทที่ 2) จัดเรียงลำดับไว้ให้เรียบร้อย (FR-SKL-01)
2. **การประเมินผล (Grading):** เมื่อสอนจบในแต่ละหัวข้อ คุณครูเปิดแท็บเล็ต แล้วจิ้มให้คะแนนเด็กแต่ละคนเป็นเปอร์เซ็นต์ (%) พร้อมเขียนคอมเมนต์สั้นๆ (Feedback) ทิ้งไว้ (FR-SKL-02, FR-SKL-03)
3. **การประมวลผลอัตโนมัติ (Auto-update):** หากระบบมีการสั่งการบ้านไว้ พอครูตรวจการบ้านเสร็จ ระบบสามารถนำคะแนนนั้นมาบวกอัปเดตใส่ในการ์ดพลังให้อัตโนมัติเลยก็ได้ (FR-SKL-05)
4. **โชว์ผลงาน (Parent View):** ผู้ปกครองเปิด LINE LIFF App เข้ามาดู จะเห็นคะแนนของลูกเป็นกราฟสวยงาม ดูความก้าวหน้าได้เป็นรายเดือนหรือรายเทอม (FR-SKL-04, FR-SKL-06)
5. **ระบบสร้างแรงจูงใจ (Gamification):**

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **การสั่งการบ้าน (Assign):** คุณครูสร้างการบ้านในระบบ โดยพิมพ์คำสั่ง, กำหนดวัน-เวลาส่งงาน (Deadline), และสามารถแนบไฟล์ (เช่น PDF ใบงาน หรือรูปภาพโจทย์) ได้ (FR-HW-01)
2. **การแจ้งเตือน (Notification):** ทันทีที่ครูกดสั่งงาน ระบบจะส่งข้อความแจ้งเตือนผ่าน LINE ไปหานักเรียนและผู้ปกครองให้รับทราบทันที (FR-HW-02)
3. **ระบบทวงงานอัตโนมัติ (Reminder):** หากใกล้ถึงวันกำหนดส่ง (ล่วงหน้า 1 วัน) แล้วเด็กยังไม่ได้ส่งงาน ระบบจะยิงข้อความไปเตือนอีกครั้งอัตโนมัติเพื่อป้องกันการลืม (FR-HW-05)
4. **การส่งงาน (Submission):** นักเรียน (หรือผู้ปกครองทำให้) เปิดแอป ถ่ายรูปกระดาษการบ้าน หรือเลือกไฟล์ในมือถือ แล้วกดอัปโหลดส่งกลับเข้าระบบ (FR-HW-03)
5. **การตรวจงาน (Grading & Feedback):** คุณครูเปิดระบบเพื่อดูรูปการบ้านที่เด็กส่งมา กดให้คะแนน และพิมพ์คอมเมนต์ (Feedback) กลับไปให้เด็ก (FR-HW-04)
6. **สถานะการบ้าน (Status Tracking):** ในหน้าจอข้อมูลนักเรียน จะมีป้ายสถานะบอกชัดเจนว่าการบ้านชิ้นไหน "ค้างส่ง" หรือ "ส่งแล้ว" เพื่อให้ผู้ปกครองและครูติดตามได้ง่าย (FR-HW-06)

### 1. [สรุปคอนเซปต์แบบบ้านๆ]

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **การรับชำระเงิน (Record Payment):** พนักงานเคาน์เตอร์บันทึกการรับเงิน เลือกว่าเด็กจ่ายค่าคอร์สไหน จ่ายด้วยวิธีใด (เงินสด/โอน) ใส่จำนวนเงิน และสามารถบันทึกส่วนลดหรือโปรโมชันที่ใช้ได้ (FR-PAY-01, FR-PAY-08)
2. **การตรวจสลิปอัจฉริยะ (AI Slip Verification):** ผู้ปกครองสามารถส่งสลิปโอนเงินผ่านทาง LINE ได้ และระบบจะมี AI ช่วยตรวจสอบความถูกต้องของสลิป (เช่น เช็คยอดเงิน, ชื่อบัญชี) เพื่อลดภาระพนักงาน (FR-PAY-02)
3. **การออกใบเสร็จ (Auto-Receipt):** เมื่อการชำระเงินสมบูรณ์ ระบบจะสร้าง "ใบเสร็จดิจิทัล (ไฟล์ PDF)" พร้อมสร้างเลขที่ใบเสร็จ (Invoice No.) และส่งไฟล์นั้นเข้า LINE ผู้ปกครองอัตโนมัติ (FR-PAY-03)
4. **ระบบช่วยขาย (Sales & Renewal Alert):**
* เมื่อนักเรียนมาสแกนเข้าเรียนจนโควต้าเหลือแค่ 2-3 ครั้ง ระบบจะแจ้งเตือนทั้งครูและผู้ปกครองให้ทราบ (FR-PAY-04)
* ระบบสามารถส่งข้อความเสนอขายคอร์สถัดไป พร้อมแนบโปรโมชันพิเศษไปให้ผู้ปกครองทาง LINE ได้เลย (FR-PAY-05)


5. **การทำบัญชี (Reporting & Export):** ระบบจะสรุปรายงานรายได้ให้เจ้าของสถาบันดูได้ทันที (รายวัน, รายเดือน, รายปี) และสามารถกด Export ข้อมูลทางบัญชีออกมาเป็นไฟล์ Excel เพื่อส่งให้สำนักงานบัญชียื่นภาษีได้ (FR-PAY-06, FR-PAY-07)

### 1. [สรุปคอนเซปต์แบบบ้านๆ]

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **ภาพรวมรายวัน (Daily Dashboard):** ทันทีที่แอดมินหรือเจ้าของล็อกอินเข้ามา จะเห็นหน้า Dashboard สรุปข้อมูลภาพรวมของวันนั้น เช่น วันนี้มีเด็กมาเรียนกี่คน, ขาดกี่คน, ลากี่คน และมีรายรับเข้ามาเท่าไหร่ (FR-RPT-01)
2. **จับตาดูความเสี่ยง (Retention & Churn):**
* ระบบจะวิเคราะห์ข้อมูลแล้วเตือนว่า มีนักเรียนคนไหนบ้างที่ขาดเรียนบ่อย หรือคอร์สใกล้หมดแล้วยังไม่ต่ออายุ ซึ่งจัดอยู่ในกลุ่ม "เสี่ยงที่จะเลิกเรียน (Churn Risk)" เพื่อให้แอดมินรีบโทรไปดูแล (FR-RPT-02)
* แสดง "อัตราการต่อคอร์ส (Renewal Rate)" เพื่อดูว่านักเรียนเก่ากลับมาซื้อคอร์สซ้ำกี่เปอร์เซ็นต์ (FR-RPT-03)


3. **ติดตามผลการตลาด (Marketing Analytics):**
* วิเคราะห์ว่าเด็กที่มา "ทดลองเรียน (Trial)" ตัดสินใจจ่ายเงินสมัครเรียนจริงกี่คน (Trial Conversion) (FR-RPT-04)
* ติดตามว่าเด็กคนไหนเป็นคนชวนเพื่อนมาสมัครเรียนบ้าง (Referral Tracking) เพื่ออาจจะให้รางวัลหรือส่วนลด (FR-RPT-07)


4. **พยากรณ์และการเงิน (Financial & Payroll):**
* ระบบช่วยพยากรณ์ (Forecast) ล่วงหน้าว่าเดือนหน้าสถาบันน่าจะมีรายได้ประมาณเท่าไหร่ จากคอร์สที่กำลังจะหมดอายุ (FR-RPT-05)
* ระบบสรุปรายงาน "ชั่วโมงสอน" ของครูแต่ละคนในเดือนนั้นๆ เพื่อเอาไปคำนวณจ่ายเงินเดือน (ค่าตอบแทน) ได้อย่างถูกต้อง (FR-RPT-06)

### 2. [ขั้นตอนการทำงาน (Step-by-Step Flow)]

1. **การจัดการตารางและสถานที่ (Calendar & Rooms):**

* **จัดห้องเรียน:** เมื่อสร้างตารางสอน ระบบจะตรวจสอบการจองห้องเรียน (Room Booking) เพื่อป้องกันไม่ให้จัดคลาสซ้อนทับกันในห้องเดียวกันเวลาเดียวกัน (FR-OPS-02)


2. **การสนับสนุนการสอนและบุคคล (Materials & Payroll):**
* **คลังเอกสาร:** ครูสามารถอัปโหลดไฟล์ หรือใบงาน เข้าไปเก็บในคลัง (Class Material Library) เพื่อใช้ประกอบการสอน (FR-OPS-03)
* **เงินเดือนครู:** ระบบจะนำชั่วโมงที่ครูสอนจริง (Teacher Payroll) มาคำนวณเป็นค่าตอบแทนให้อัตโนมัติ (FR-OPS-04)


3. **ความปลอดภัยและกฎหมาย (Security & Compliance):**
* **PDPA:** ระบบมีหน้าต่างให้ผู้ใช้งานกดยินยอมและจัดการหลักฐานความยินยอมตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (FR-OPS-05, NFR-C-01 ถึง 04)
* **การสำรองข้อมูล:** ระบบทำการ Backup ข้อมูลทั้งหมดอัตโนมัติทุกวัน เพื่อความปลอดภัย (FR-OPS-06, NFR-R-02)


4. **การพัฒนาคุณภาพ (Feedback):**
* ระบบสามารถส่งแบบสำรวจความพึงพอใจ (NPS Survey) ให้ผู้ปกครองประเมินเป็นรายไตรมาส (FR-OPS-07)

### 1. [สรุปคอนเซปต์แบบบ้านๆ]

หมวดนี้เปรียบเสมือน **"เครื่องยนต์ โครงเหล็ก และระบบเบรกของรถยนต์"** ครับ

ฟีเจอร์ 11 ข้อที่ผ่านมาคือ "พวงมาลัย เบาะนั่ง แอร์" ที่ผู้ใช้งานมองเห็นและจับต้องได้ แต่ NFR คือสิ่งที่ซ่อนอยู่ข้างใน เพื่อรับประกันว่ารถคันนี้จะ **"วิ่งเร็ว (Performance) ไม่พังง่าย (Reliability) ป้องกันขโมย (Security) ขับง่าย (Usability) และถูกกฎหมายจราจร (Compliance)"** ถ้าระบบมีฟีเจอร์ครบแต่สอบตกหมวดนี้ ระบบจะช้า ล่มบ่อย และเสี่ยงถูกฟ้องร้องครับ

### 2. [รายละเอียดกฎเหล็ก 5 ด้าน (The 5 Pillars)]

**ด้านที่ 1: ความเร็วและประสิทธิภาพ (Performance - NFR-P)**

* หน้าเว็บต้องโหลดเสร็จภายใน 3 วินาที (เน็ต 4G)
* **สำคัญมาก:** สแกน QR เช็คชื่อต้องจบภายในไม่เกิน 2 วินาที (ห้ามให้เด็กยืนรอคิวหน้าประตูนาน)
* ระบบต้องทนรับคนใช้งานพร้อมกัน (Concurrent) ได้ 100 คน โดยที่ Database ห้ามหน่วงเกิน 200ms

**ด้านที่ 2: ความปลอดภัยขั้นสูง (Security - NFR-S)**

* รหัสผ่านต้องถูกสับละเอียด (เข้ารหัส bcrypt/argon2) ห้ามใครเห็นรหัสจริงแม้แต่เจ้าของระบบ
* QR Code ของเด็กต้องไม่ใช่รูปภาพธรรมดา แต่เป็น **"รหัสที่หมุนเวียนเปลี่ยนไปเรื่อยๆ (Rotating Token 30-60 วิ)"** เพื่อกันเด็กแคปหน้าจอส่งให้เพื่อนสแกนแทน
* ป้องกันการโจมตีจากแฮกเกอร์ (SQL Injection, XSS) และมีระบบเตะ Admin ออกอัตโนมัติหากเปิดจอทิ้งไว้ 30 นาที

**ด้านที่ 3: ความทนทานและการสำรองข้อมูล (Reliability & Backup - NFR-R)**

* ระบบต้องเปิดใช้งานได้ 99.5% ของเวลาทั้งหมด (ห้ามล่มบ่อย)
* ต้องมีการ Backup ข้อมูลทุกวัน และถ้าสมมติ Server ไฟไหม้ ต้องกู้ข้อมูลกลับมาให้โรงเรียนใช้งานได้ภายใน 4 ชั่วโมง

**ด้านที่ 4: ความง่ายในการใช้งาน (Usability - NFR-U)**

* ครูต้องสแกนเช็คชื่อเด็กได้จบใน "3 คลิก" (เปิด -> สแกน -> ยืนยัน)
* ผู้ปกครองต้องใช้งานผ่าน LINE ได้ทันที **"โดยไม่ต้องโหลดแอปใหม่"**
* หน้าจอรองรับมือถือ แท็บเล็ต และคอมพิวเตอร์อย่างสมบูรณ์แบบ (Responsive)

**ด้านที่ 5: การปฏิบัติตามกฎหมาย (Compliance - NFR-C)**

* ต้องมีระบบจัดการ PDPA อย่างเคร่งครัด ผู้ปกครองมีสิทธิ์ขอลบข้อมูลลูกทิ้งได้ (Right to be Forgotten) และขอ Export ข้อมูลออกไปได้
* ใบเสร็จรับเงินต้องถูกต้องตามมาตรฐานสรรพากรไทย

### 3. [ตารางสรุปผลกระทบต่อสถาปัตยกรรมระบบ]

กฎเหล็กเหล่านี้ บังคับให้เราต้องเลือกใช้เทคโนโลยีตามที่ SRS ระบุใน **หมวด 5 (สถาปัตยกรรม)** ดังนี้:

| กฎเหล็ก (NFR) | เทคโนโลยีที่ต้องใช้ (Tech Stack) | อธิบายแบบบ้านๆ |
| --- | --- | --- |
| **ความเร็ว (Performance)** | `Next.js`, `Vercel`, `Edge Functions` | เอาเว็บไปวางไว้บน Server ระดับโลก เพื่อให้โหลดเร็วปรู๊ดปร๊าด |
| **ความปลอดภัย (Security)** | `Supabase Auth`, `TLS 1.2+` | ใช้ระบบล็อกอินมาตรฐานสากล แทนการเขียนระบบล็อกอินเอง |
| **ไม่ต้องโหลดแอป (Usability)** | `LINE LIFF SDK`, `LINE Messaging API` | ฝังแอปของเราเข้าไปในแอป LINE ให้ผู้ปกครองเปิดผ่านแชทได้เลย |

================================================================================
TITLE: การตั้งค่าสถาปัตยกรรมระบบ และบังคับใช้ NFR (System Architecture & NFR Enforcement)
================================================================================

[USER STORY]
- As a: System Architect / DevOps Engineer
- I want to: ตั้งค่าโครงสร้างพื้นฐานของระบบให้ตรงตาม NFR (ความเร็ว, ความปลอดภัย, ความทนทาน)
- So that: ระบบมีเสถียรภาพ รองรับการขยายตัว และไม่ละเมิดกฎหมายความปลอดภัยของข้อมูล

[BUSINESS LOGIC / RULES]
1. Security Standard: ห้ามเก็บ Plain-text password, บังคับใช้ HTTPS, เปิดใช้งาน CORS และ Rate Limiting อย่างเคร่งครัด (NFR-S-01 ถึง 05)
2. Data Retention & Backup: ตั้งค่า Automated Backup ประจำวันบน Database Provider เก็บย้อนหลังอย่างน้อย 30 วัน (NFR-R-02)
3. QR Token Rotation: ต้องเขียน Logic สำหรับ TOTP (Time-based One-Time Password) หรือ JWT แบบอายุสั้นมาก (30-60s) สำหรับการสร้าง QR Code ของนักเรียน (NFR-S-07)
4. APM & Monitoring: ต้องมีเครื่องมือจับเวลา Database Query (ต้อง <200ms) และ Page Load Time เพื่อเฝ้าระวังประสิทธิภาพ (NFR-P-01, 05)

[ACCEPTANCE CRITERIA (AC)]
[ ] 1. (DevOps) ตั้งค่า CI/CD Pipeline และ Deploy Frontend บน Vercel พร้อมบังคับใช้ HTTPS
[ ] 2. (Database) ตั้งค่า Supabase (PostgreSQL) พร้อมเปิดใช้งาน Automated Backups และ Row-Level Security (RLS)
[ ] 3. (Backend) เขียน Utility สำหรับการเข้ารหัสรหัสผ่าน และระบบ Auth Session Timeout
[ ] 4. (Backend) สร้าง Algorithm ระบบ Rotating QR Code ที่ฝั่ง Client สร้าง Token ที่หมดอายุใน 60 วินาทีได้
[ ] 5. (QA) ทำการ Load Test (เช่น ใช้ JMeter/K6) จำลอง 100 Concurrent users ยิง API เช็คชื่อ ให้ผ่านเกณฑ์ < 2 วินาที
================================================================================
